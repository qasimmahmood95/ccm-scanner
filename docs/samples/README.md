# Sample reports

Committed output, regenerated by `npm run samples:update`, so the shape of an
evidence pack can be read without running anything.

| Directory | Input | Headline |
| --- | --- | --- |
| `terraform-compliant/` | `fixtures/compliant/terraform-plan.json` | PASS |
| `terraform-non-compliant/` | `fixtures/non-compliant/terraform-plan.json` | FAIL |
| `snapshot-non-compliant/` | `fixtures/snapshot/non-compliant.json` | FAIL |

Each holds `report.json` (the machine-readable pack, validated against
`schemas/report.schema.json`) and `summary.md` (the human-readable one).

All three are generated with a fixed `--generated-at`, so they are
byte-reproducible and a diff shows a real change in what the scanner concluded
rather than a new timestamp.

The two non-compliant packs are worth comparing. They describe the same
infrastructure, and they agree on every control except one: the plan cannot know
`aws_ebs_volume.data.encrypted` until apply and declines it, while the snapshot
observed the volume unencrypted and fails it. See
[ADR-0004](../adr/0004-snapshot-lane.md).
